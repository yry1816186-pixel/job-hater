## 三、可用命令清单

### 用户命令（Claude Code 技能，已装 ~/.claude/skills/ 共 8 个）

| 命令 | 功能 | 使用示例 |
|------|------|----------|
| `/profile` | 导入/更新个人信息、简历、作品集 | "把这份实习证明更新进我的画像" |
| `/search` | 校招岗位导入+五维评分排序 | "帮我找南京的 AI 产品校招岗" |
| `/apply` | 定制简历+求职信+打招呼话术（真实性+风控双闸门） | "给这个岗位出投递材料并记录" |
| `/interview` | 面试题库+模拟面试（证据锚定） | "下周 XX 公司二面，帮我模拟" |
| `/pipeline` | 投递进度看板+状态管理 | "现在投递情况怎么样" |
| `/upskill` | 技能缺口+14/30/60 天冲刺计划 | "我还差什么，30 天怎么补" |

### CLI（`python3 core/cli.py`，可独立于 Claude 使用）

```bash
profile --validate --show          # 画像校验+摘要
ingest --file f.json --source boss # 岗位导入（清洗/去重/校招过滤）
search [--min-score 65] [--city 南京] [--keyword 后端] [--job <id>]
apply --job <id> [--send]          # --send 过风控后记账并更新黑名单
interview --job <id> | --skills "Python,LLM"
pipeline                           # 看板+待投递高优推荐
upskill --job <id> | --keyword "方向"
blacklist [--add 公司名]
```

## 五、每步反思结论（全文见 docs/反思优化报告.md）

1. **拉取**：career-ops 已迁移至 career-ops-hq（不核实就会误判"不存在"）；codeload 不支持断点续传（伪方案实测识破）→ 整包+4 worker 并行；7/7 全部落地
2. **调研**：任务点名的 mcp-jobs 与 OpenHire 均证实存在，但"存在"≠"可用"——逐一实测区分待遇
3. **融合**：闸门先于评分（过滤层硬排除而非降权）；factcheck 上线即拦下自家生成器 6 处缺口（修证据不放宽校验）；单元测试抓到"10年"经验解析漏网
4. **定向**：年限"权重0"实现为过滤层硬排除；薪资倒挂用保守常数表并标注启发式属性
5. **入口**：第三方 README 与包不同步（npx 不可用）→ 自研 wrap_stdio.js 卫生包装器

## 六、降级路径说明（全文见 docs/降级路径说明.md）

- **粘贴导入是永远可用的完整功能路径**（清洗→过滤→评分→简历全链路）；所有平台采集方案均有诚实状态标注
- mcp-jobs / get_jobs / Playwright chromium / 全自动投递：各自的受限原因与本地启用步骤已写明
- 真实站内投递采用**半自动**（系统管风控+台账，人工 30 秒完成站内动作）——这是设计决策而非缺陷
