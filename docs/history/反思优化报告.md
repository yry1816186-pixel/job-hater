# 反思优化报告 — 每一步的回头审视

> 按执行顺序记录：每完成一步回头问"有没有更好的方法？有没有隐患？"，以及据此做的修正。

## 第一步反思：项目拉取

**发现的问题**
1. 网络被限速（~18KB/s）+ 间歇 TLS 瞬断，7 个仓库 4 个反复克隆失败；
2. `santifer/career-ops` 已迁移至 `career-ops-hq/career-ops`（API "Moved Permanently" 发现，72k stars）——提示词里的旧地址若不核实就会当成"项目不存在"；
3. `curl -C -` 对 codeload.github.com 无效（不支持 Range，断点续传是伪方案）——第一版续传脚本文件不增长暴露了这一点。

**修正**
- 换整包下载 + 4 worker 并行 + 无限重试；每一次策略切换都基于实测诊断，而非盲目重试。

## 第二步反思：深度调研

**关键收获**
1. **任务点名的两个 MCP 项目都被证实真实存在**：mcp-jobs（npm v1.4.0）与 OpenHire（PyPI openhire 0.6.0）。前者当前版本实测不可用（缺 bin、启动阻塞、爬取配置过期），后者完整可用——两者待遇如实区分；
2. 调研 agent 用「git clone + GitHub API + 直接 HTTP 抓取」三重验证替代被拦截的 WebFetch——验证手段本身也要反爬优先；
3. 发现多个 2027届/校招特化项目（job-radar、xiaozhao-radar、offer-harvester 等），说明"校招定向"不是我们的独创，而是社区共识方向，其信源列表值得吸收。

**自我质疑**：调研是否足够？→ 引入坚持"宁缺毋滥"：所有清单项必须有当日实测核验，star 数与"看起来厉害"不作为引入理由。

## 第三步反思：核心融合

**架构决策与理由**
1. 「闸门先于评分」（来自 ai-job-search 的 Eligibility Gate 模式）：≥1年经验/猎头/外包/过期在过滤层直接出局，不进评分——若混进评分会被高分稀释，这是原则性错误；
2. 双Agent机制拆成「LLM审核 + 机器factcheck」两层：机器层保证数字/引用100%可溯，LLM层负责语义核验。对抗测试暴露了机器层的真实边界（纯文字捏造无法识别）——如实写进降级文档而不是掩盖；
3. 评分引擎做成纯函数（同输入必同输出）：评分可复现才可解释，可解释才可信任。

**测试驱动的真实修复（不是摆设）**
- factcheck 上线即拦下自己生成器的 6 处溯源缺口（奖项全称、毕业时间推导）——先修证据原文，绝不放宽校验器；
- 单元测试抓到「10年Java」经验解析漏网——修复正则并用环视排除 `2026年` 误匹配。

## 第四步反思：2027届定向

1. 工作年限"权重置0"实现为**过滤层硬排除**而非评分0权重——两者效果不同：前者保证用户永远看不到不合格岗位，后者只是排序靠后；
2. 薪资倒挂检测用保守城市常数表（启发式，标注为提示而非否决）——诚实标注不确定性比假装精确好；
3. 打招呼话术/求职信全部走 evidence 锚定 + factcheck——文案生成器是造假高发区，恰恰要最严。

## 第五步反思：入口与体验

1. `npx -y mcp-jobs` 按 README 会失败（包缺 bin）——第三方文档与包不同步是常态，**一切以实测为准**；写了 `wrap_stdio.js` 卫生包装器解决其 stdout 污染；
2. 技能同时安装到 `~/.claude/skills/`（用户级）保证任意目录可用；
3. 首次引导写进主 SKILL.md（`profile --show` 起手 + 一句话介绍六命令）。
