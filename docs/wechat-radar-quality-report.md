## 2. 性能

- **密钥扫描**：自研 AES-NI C 扩展（MSVC /O2），较纯 Python 提速 **40×**——
  7GB 全进程全区域逐字节穷尽 **353 秒**（13 进程并行）；随机最坏 10MB 零误报。
- **解密**：1.2GB 消息库预估分钟级（顺序读 + AES-NI 级吞吐）。
- **识别**：单条微秒级；百万消息预估 1-2 分钟（正则 30+ 条/条）。
- 生产路径 `find_key` 单线程兜底版 ~10-40 分钟（进度可见），hex 命中场景分钟内。

## 3. 准确性

- 密钥验证 **HMAC-SHA512 终审，密码学级零假阳性**（2^-256）。
- 识别引擎 22 用例：正样本（校招/内推/实习/社招 JD）命中且字段断言；
  负样本（求职提问/闲聊/保研通知/裁员新闻）拒收；届别跨年（2026/2027）正确。
- 每条命中携带**证据链**（触发规则清单）与置信度，UI 可查——可审计、可纠错。

## 4. 科学性

- **多假设系统排除法**定位密钥形态：9 种形态（raw×4 对齐 / hex ASCII/UTF-16 /
  x'..' / 指针间接 / PBKDF2 密码）× 全区域类型 × 逐字节，全部以可复现脚本执行。
- 结论可证伪：每一步扫描有日志与计数（chunks/candidates/hits）。
- 无黑箱：识别引擎全部规则透明，权重显式（意图 0.22 / 公司 0.20 / 岗位 0.18 …）。

## 5. 可视化

- 结果卡片：公司/岗位/届别/类型/城市/薪资/截止标签化 + 置信度分级配色 +
  原文与识别依据折叠可查 + 来源（群名/发送者/时间）。
- 扫描进度：六阶段文案 + 动画条 + 实时明细 JSON。
- 命令面板（Ctrl+K）收录「微信招聘雷达」直达。

## 6. 实用性（零编程使用）

- 拉取项目 → `pip install -e ".[wechat]"` → 打开界面 → 点一个按钮。
- 环境不满足时**可行动指引**（如「请先打开微信并登录」），不是裸报错。
- 导入统一走项目 ingest（去重/规范化/FTS），与手工/扩展/官网信源无缝共存。

## 7. 安全与隐私

- 密钥**只在内存流转**，绝不落盘（E2E 断言密钥不出现在任何产物）。
- 解密产物独立于微信本体目录，`DELETE /api/wechat/data` 一键清除。
- 只读微信文件 + 只读进程内存；不写微信任何数据；不上传任何内容。

### 补充：密钥检索能力升级（2026-09-22 追加批次）

`keyring_scan` 已产品化社区已知最强方法（WeChatDataAnalysis 等公开实现的机制复现）：

- **密码式验证**：`verify_as_password`——新版 WCDB 内存存 passphrase（每库 PBKDF2-256000
  派生 enc_key），与既有 encKey 直通式并存；
- **DLL XOR 混淆密钥提取**：`dll_xor_keys`——从 Weixin.dll 代码段 `4×mov rdx,imm64`
  模式提取混淆密钥（安装目录自动发现，含版本子目录）；
- **双布局结构定位**：`[ptr][0×8][32][47]` 容器签名与 MSVC `std::string [ptr][size=32]`
  两种布局的指针解引用候选（熵筛后验证）。

本机 4.1.15.13 实证该机制被新版密钥保护关闭（3836+7110 候选全量验证无命中，
AES-NI C 扫描器 7GB 逐字节穷尽同样排除直接形态）；产品现在具备社区已知全部
提取能力，版本回退或社区适配新布局后无需改代码即可命中。

**UI 目视验收**：Playwright 独立实例截图 + visual-judge 判定通过（环境卡正确
渲染微信 4.1.15.13 / 双账号 / 1068MB 消息库；布局无错乱、无溢出、控件完整）。

### 补充 2：本机实测全链路打通 + 识别引擎实测校准（2026-09-22 晚批次）

**密钥捕获成功**：微信重启（自动登录）瞬态窗口内，组合捕获器（C 扫直通 encKey
+ 结构定位 passphrase + 候选立即落盘）收集 1342 个 passphrase 候选，多进程并行
验证（直通 + DLL XOR 形态）约 45 秒命中。关键工程改进：**候选落盘与验证进程
分离**——验证进程死亡不丢候选、捕获进程死亡不影响验证（此前单进程架构曾因
会话中断丢失 1099 个候选）。

**产品化落点**：`JOBHATER_WECHAT_KEY` 直通通道升级为双形态——直通式（某库
enc_key）优先、**密码式（passphrase，每库 PBKDF2 派生）回退**，且不再依赖
微信进程/平台（离线可用）。测试覆盖（`test_find_key_env_password_fallback`）。

**全量实测结果**（本机 2 账号、9 库、1069MB 消息库）：

| 指标 | 数值 |
|------|------|
| 消息总量 / 可分析 | 728,740 / 728,675 |
| 招聘相关命中 | 2,147（平均置信 0.653） |
| 类型分布 | 校招 1165 / 实习 213 / 社招 12 / 升学招生 90 / 未分类 667 |
| 届别分布 | 2027:35 / 2026:54 / 2025:96 / 2024:5 / 2028:1 |
| 2027 届构成 | 真就业 16 + 升学通知 19（后者标记 edu 不入岗位库） |
| 导入岗位库 | 14 条（去重 1 条） |

**实测驱动的引擎校准**（每项均有测试锁定）：

1. **升学招生过滤**：推免/保研/夏令营等研究生招生通知曾以 0.82-1.00 置信混入
   （19/35 条 2027 命中是噪声）。新增 `EDU_ADMISSION_WORDS` 强信号词典，
   命中标记 `kind="edu"` 并压分 55%——雷达页可见（升学也是有效信息）但不再
   进入岗位库；
2. **品牌最长匹配**：「京东方」被子串「京东」抢先命中。品牌词典改为最长优先
   序（`_BRANDS_BY_LEN`）；
3. **群名不入雇主字段**：「艺术学院2023级脆皮本科生群」等群名曾被后缀模式
   抽成公司名。发送者/群名兜底现在拒绝含「群」字的名字；导入兜底改用
   「未知公司（微信）」占位；
4. **title 拒绝 URL**：标签值是链接（kdocs 投递表等）不再被当岗位名；
5. **雷达页渲染上限**：2147 条命中全量渲染会卡死页面。列表截断 100 条 +
   超出提示用筛选缩小。

**UI 验收**（浏览器实测）：2027 届筛选出 35 条，16 条真就业命中完整展示
（长城证券/网易/联想/京东方/搜狐畅游×2/海尔/美团/阿里巴巴/腾讯等，置信度
70-100%，来源群+发送者+时间+投递方式齐全），升学通知带「升学招生」标签区分。

## 8. 已知限制（如实说明）

- ~~本机微信 4.1.15.13 运行态未在可读内存中发现密钥~~ → **已解决**（登录瞬态
  捕获，见补充 2）。稳态密钥仍不可见：常规使用请**重启微信后立即扫描**，
  或用 `JOBHATER_WECHAT_KEY` 直通（支持 passphrase）。
- 图片/语音消息内容不参与识别（仅文本与链接卡片）；公众号图文取正文摘要。
- 置信度阈值为经验值，UI 可调；误报以「疑似求职方」标签透明提示。
- 单条级品牌误匹配仍存在（如新东方帖正文含腾讯字样时公司字段误标为腾讯；
  多岗位汇总帖按首命中公司）——证据链透明可人工核查，暂不做上下文级消歧。
- ~~岗位收件箱（/jobs）暂无届别/来源筛选参数~~ → **已修**（2026-09-22 晚第二批）：
  `graduation_year` 从 ingest 透传进 extras（此前被静默丢弃）、search/count_filtered
  支持 `json_extract` 届别与来源过滤、`GET /api/jobs` 暴露两参数、收件箱加届别
  下拉。雷达页扫描失败的引导文案也同步补上（重启微信→立即扫描）。
