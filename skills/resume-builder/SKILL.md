# Resume Builder — 双Agent定制简历与投递

## 命令

```bash
python3 core/cli.py apply --job <id>              # 生成材料（真实性校验必过）
python3 core/cli.py apply --job <id> --send       # + 风控闸门通过后记录投递
```

产出（`data/out/<job_id>/`）：`resume.md`（用户版）、`resume.audited.md`（审计版含证据引用）、
`cover_letter.md`、`greeting.md`。

## 双Agent工作流（融合 ai-job-search 的 Drafter-Reviewer 机制）

### 第一步：起草Agent（Claude）
1. `search --job <id>` 读评分详情（技能缺口旗标优先看）；
2. `python3 core/cli.py apply --job <id>` 生成**确定性基线版**（引擎自动完成：
   应届生结构排序、经历按JD相关度重排、技能重排、事实全锚定）；
3. 在基线版之上做 LLM 润色——**只允许三种操作**：
   - 重新排序（把与JD最相关的往前放）
   - 重新措辞（把JD同义关键词自然融入已有事实，如JD写"大模型"原文写"LLM"）
   - 调整侧重（同一事实强调不同侧面）
   **新增任何事实、数字、经历=违规**，factcheck 会拦截，但不要依赖拦截，起草时就自律。
4. 润色后仍保留全部 `[ev:...]` 引用标记。

### 第二步：审核Agent（独立视角，逐条核验）
把起草Agent的产出交给审核流程（可派子代理，保持独立性），按三维度评审：
1. **真实性**：逐条对照 `data/profile/profile.json` 的 evidence_index，
   每条经历/数字必须能在证据原文找到；找到不了的一律标记删除；
2. **关键词匹配**：JD核心关键词是否已自然覆盖（同义替换OK，编造经历凑关键词不行）；
3. **ATS通过率**：标题清晰、关键词密度合理、无花哨排版、量化成果前置。

审核发现的修改，由起草Agent执行后**重跑 `apply` 命令**，机器 factcheck 必须输出
`✅ 真实性校验通过` 才算完成。机器报告是硬闸门，LLM自评不能替代。

### 第三步：风控与投递
- `--send` 前系统自动检查：单平台每日≤25份、消息间隔≥30s、敏感时段（22:00-08:00）禁投、
  黑名单去重。被拦截时向用户解释原因，建议调整时间/渠道，**不要绕过**；
- 真实站内投递需要平台浏览器会话（见 adapters/）。本系统的 `--send` 是台账记录+风控记账，
  站内动作由用户半自动完成（打开平台→粘贴 greeting.md→发送→回来说一声）。

## 打招呼话术规范（应届生风格）

- ≤120字，首句身份+最硬的匹配点（EI一作/国一奖项），中段契合点，尾句诚意+可面试时间；
- 突出学习意愿，不用"精通"，不卑不亢；
- 禁止模板腔"贵司平台大发展好"，要有岗位具体信息。

## 用户材料更新联动

生成时若发现用户提到的经历画像里没有：停下，先走 profile-manager 流程回写证据，
再生成。宁可多一轮，不可替用户"先写上"。
